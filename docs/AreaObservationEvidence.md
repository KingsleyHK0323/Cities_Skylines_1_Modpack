## 2026-11-07 startup-unlock research

The product goal is now to unlock all 25 areas at the start without debiting city funds; treatment of existing saves remains undecided. The following is static IL evidence from the same authorized Assembly-CSharp.dll above, not evidence that an in-game write is safe:

- `GameAreaManager.get_MaxAreaCount` assigns a default of 9 when its backing field is zero. The `IAreas.maxAreaCount` implementation in `AreasWrapper` clamps writes to 1–25 and may notify milestones; changing that maximum alone does not prove that a tile can be unlocked.
- `GameAreaManager.GetTileIndex(Int32, Int32)` returns `z * 5 + x` (IL_0000–0005). In the same assembly, `IsUnlocked(Int32, Int32)` checks both coordinates are in 0–4 before reading `m_areaGrid[z * 5 + x]` (IL_0000–0030); `AreasWrapper.IsAreaUnlocked` delegates to it (IL_0000–000D). This supports validation of labels for this 5-by-5 assembly copy only; it does not verify actual callback provenance, modified game versions or 81-area mapping.
- `GameAreaManager.CanUnlock` also checks `UnlockManager.Unlocked(areaCount)`, ownership, and adjacency. `UnlockManager.Unlocked(Int32)` uses a clamped index into the configured area-milestone array. The actual milestone data and any overriding extensions have not been verified.
- `ICities.IAreas.UnlockArea(x, z, requireMoney)` and `AreasWrapper.UnlockArea` return void. The wrapper invokes its implementation immediately on the simulation thread and queues it otherwise. `UnlockAreaImpl` uses `requireMoney` to control price calculation; `false` follows a path that does not call `EconomyManager.FetchResource` in this inspected implementation. A nonzero calculated amount on the other path is fetched before `GameAreaManager.UnlockArea` is called. Other extensions or patched behavior are not covered; the return or queue operation does not establish success or prove the city's funds remain unchanged.
- The wrapper converts the raw coordinates to `z * 5 + x` before `GameAreaManager.UnlockArea` reconstructs the coordinates; the inspected wrapper does not first reject raw out-of-range coordinates. For example `(5, 0)` and `(0, 1)` both map to index 5, while `(-1, 1)` and `(4, 0)` both map to index 4. Actual unlocking remains subject to `CanUnlock`. Candidate inputs reject the out-of-range examples; any future write adapter must independently revalidate raw x and z in 0–4 at the call site.
- `GameAreaManager.UnlockArea` checks eligibility, updates the area grid and count, updates zones, then attempts a detailed terrain patch. A failed terrain patch reverts the grid and count in the inspected path; this alone does not establish a complete rollback of every side effect.
- `GameAreaManager.Data.Serialize` writes the area count and starting tile as bytes followed by the encoded area-grid entries. Deserialize reads the count, sets the maximum to at least that count, and reads entries into the existing grid. This does not establish the safety of 25-area saves, version migration, removal, or 81-area saves, and no save was read or modified.
